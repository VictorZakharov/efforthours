# Repository work-item rubric with manual-QA correction 1.0.0

## Purpose

This is a composition rubric for a development-only calibration corpus. It does
not authorize a model, change the shipped estimator, or reinterpret existing
reviewed values.

The compiler governed by
`manual-qa-development-review-compiler/1.0.0` applies two frozen rubrics by
category:

- every target outside
  `manual-validation-debugging-and-hardening` remains byte-for-byte semantic
  content from `ehe-work-item/1.1.0`; and
- every replacement `manual-validation-debugging-and-hardening` target comes
  from a completed candidate-blind decision under
  `manual-qa-work-item/1.0.0`.

The corpus-level reference uses this composition identity because the v1 corpus
contract has one rubric reference while the corrected corpus intentionally
contains both preserved and replacement categories.

## Compilation boundary

The compiler must:

- preserve the 1,710 non-QA targets, their reviewed ranges, rationales,
  uncertainty, size exceptions, evidence, and source work-item lineage;
- remove all 320 legacy manual-QA targets;
- add exactly one manual-QA target for each of the 955 frozen eligible coding
  responsibilities;
- map every added target to the exact candidate QA work-item IDs derived from
  its hidden source-work-item lineage under
  `manual-qa-source-work-item-lineage/1.0.0`;
- retain explicit zero exclusions and duplicates as zero targets so false
  positives remain measurable;
- preserve public source and reviewer provenance without source excerpts or
  private paths; and
- produce deterministic output independent of record or decision input order.

The compiler may not infer, rescale, reconcile, smooth, or replace a completed
review judgment. It may only validate, map, preserve, replace the named category,
and serialize.

## Interpretation

The resulting labels remain `teacher-estimate` weak supervision. They are not
actual labor, a time study, an independently reviewed corpus, held-out
validation, or production-accuracy evidence. Candidate and seed comparisons are
a later development-only checkpoint. Validation and test remain unavailable.
